# 接口说明

[返回项目首页](../README.md)

以下路径以应用根路径为基准，默认地址为 `http://localhost:8081`。若配置了应用上下文路径，需加上对应前缀。文件路径相对于 `file.basePath`，不是服务器绝对磁盘路径。

当前接口同时包含 HTML 页面、文件流和 JSON，没有统一响应包装，也没有应用级认证机制。

## 路由一览

| 方法 | 路径 | 输入 | 行为 |
| --- | --- | --- | --- |
| GET | `/` | 无 | 重定向到 `/f` |
| GET | `/f`、`/f/**` | 目录或文件路径 | 目录返回列表页面，文件返回文件流 |
| GET | `/u` | 无 | 上传页面 |
| POST | `/upload` | multipart 表单 | 保存文件或分片，返回接收或保存完成的 JSON 回执 |
| GET | `/v1/**` | 文件路径 | 视频返回播放器页面，其他文件交给媒体接口逻辑 |
| GET | `/v2/**` | 文件路径 | 302 跳转到对应 `/v1/**`，保留原路径编码 |
| GET | `/media/**` | 文件路径，可带 Range | 返回原始文件，支持范围读取 |
| GET | `/c` | 无 | 显示当前服务器剪贴板内容 |
| POST | `/uptext` | 表单字段 `cont` | 仅记录服务器日志，无业务响应体 |
| GET | `/cbpn` | 无 | 返回先前读取剪贴板时生成的 PNG 文件，随后尝试删除 |
| GET | `/api/subtitles` | 查询参数 `path` | 返回字幕轨道元数据数组 |
| GET | `/api/subtitles/track` | 查询参数 `path`、`track` | 返回 UTF-8 WebVTT |
| GET | `/api/subtitles/track.vtt` | 查询参数 `path`、`track` | 同上，带扩展名的播放器兼容地址 |

页面加载本地静态脚本、样式、图片和 `/libmedia/` 资源，不需要独立前端资源服务。

视频页面包含当前目录的视频列表，供上一集、下一集和选集使用，按文件名自然排序；不扫描上级或子目录，也不新增选集 API。切集直接读取新文件的 `/media/**` 和字幕接口。

可选公网发现程序独立提供 `POST /api/heartbeat` 和 `GET /`，它们不是 JAR 新增的入站接口。JAR 主动发送 `addresses` 地址列表、兼容旧版的首个 `address` 和 `reportIntervalSeconds`，公网端保存最新列表和接收时间，每个地址提供单独入口；协议与部署见[公网服务发现](DISCOVERY.md#http-协议)。

该程序按单服务最新状态覆盖保存，两个地址字段同时提供时以 `addresses` 列表为准；成功返回 `204`，输入无效返回 `422`，无法保存返回 `503`。`lastSeen` 由公网服务器生成，网页状态按 `max(900 秒, 上报间隔 × 3)` 过期判断，不代表手机到 JAR 的连通性。

## 路径约定

例如共享根目录为 `D:/Downloads`，文件为 `D:/Downloads/movies/demo.mp4`：

- 浏览或下载：`/f/movies/demo.mp4`。
- 播放页面：`/v1/movies/demo.mp4`。
- 原始媒体：`/media/movies/demo.mp4`。
- 字幕查询参数：`path=/movies/demo.mp4`。

中文、空格、`#`、`%` 等应按 URL 所在位置正确编码。查询参数建议使用 `URLSearchParams`；路径应逐段编码并保留目录分隔符，避免重复编码。

## 上传协议

请求类型为 `multipart/form-data`，由浏览器或 HTTP 客户端生成 boundary。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | 字符串 | 客户端文件名；目标为上传目录下的同名文件 |
| `file` | 文件 | 当前文件或当前分片的字节内容 |
| `chunks` | 整数 | 分片总数；单请求上传省略 |
| `chunk` | 整数 | 从 0 开始的分片序号；单请求上传省略 |

单请求上传必须提供 `name` 和 `file`。多片上传还需提供 `chunks` 与 `chunk`，并遵循“首片成功 → 中间片全部成功 → 最后一片”的顺序。后端以 `chunk` 是否存在区分直接保存和分片流程，不会自动替客户端切片。

临时分片文件名为 `{chunk}-{chunks}-{name}.tmp`，放在以 `name` 命名的临时子目录；合并按索引顺序执行。该协议没有 upload ID、分片查询或断点续传 API。客户端重试失败文件时从头提交。

响应为 JSON：

- 首片和中间分片成功保存：HTTP `200`，`{"status":"chunk_received"}`。
- 整文件成功保存，或最后一片触发的合并完成、输出关闭并移入目标目录：HTTP `200`，`{"status":"completed"}`。最后一片请求会等待合并结果。
- 参数无效：HTTP `400`，`{"status":"failed","message":"…"}`；保存、合并失败或上传任务失效：HTTP `500`，相同错误结构，详细原因记录在服务器日志。

前端进度到达 100% 只表示请求数据发送完成，页面继续显示“正在保存 / 合并…”，收到 `completed` 后才显示“已上传”。空响应、HTML 或不符合预期的回执均视为未确认成功。最终请求超时或网络中断时，文件可能已经保存；页面报告未确认，不会自动重发最后一片，请先检查服务器文件。请求超时为 120 秒，经反向代理访问时也需留出合并等待时间。

合并先写入临时文件，成功后再移入上传目录；失败清理不会主动删除已有目标文件。仍按文件名管理任务，没有跨客户端同名任务隔离、任务状态查询或校验和接口。

## 字幕接口

播放器菜单中的“不使用字幕”由前端控制字幕渲染，不新增 HTTP 接口，也不使用特殊轨道 ID 表示关闭。菜单开关不会更改以下接口的响应；状态只在当前页面保留。操作说明见[视频与字幕专题](SUBTITLES.md#字幕)。

### 查询轨道

```http
GET /api/subtitles?path=%2Fmovies%2Fdemo.mp4
```

响应示例（轨道 ID、标签和语言取决于具体文件）：

```json
[
  {"id": 3, "label": "中文（第 1 轨）", "language": "zho"},
  {"id": 4, "label": "英语（第 2 轨）", "language": "eng"}
]
```

`id` 是 MP4 轨道 ID，不能当作数组下标。现存的非 MP4 文件或没有受支持 tx3g 轨道的 MP4 返回空数组。此接口不返回字幕正文。

### 获取 WebVTT

```http
GET /api/subtitles/track.vtt?path=%2Fmovies%2Fdemo.mp4&track=3
```

成功响应包含 `Content-Type: text/vtt;charset=UTF-8`、`Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。示例正文：

```text
WEBVTT

00:00:01.000 --> 00:00:03.000
示例字幕
```

### 字幕错误状态

| HTTP 状态 | 常见原因 |
| --- | --- |
| 400 | `path` 格式无效，例如不以 `/` 开头或含反斜杠；参数缺失或类型不符 |
| 403 | 路径规范化或符号链接解析后超出共享根目录 |
| 404 | 视频文件或指定字幕轨道不存在 |
| 422 | MP4 读取或解析失败、内容超出解析限制等 I/O 错误 |

以上描述状态码，不承诺统一错误 JSON 格式。

## 媒体与下载响应差异

`/media/**` 使用资源处理器支持 HTTP Range，适合播放器拖动；视频文件设置 `no-store`。无效或越界路径通常返回 404。`/v1/**` 的视频页面入口也使用同一真实路径校验。

`/f/**` 的普通下载直接输出文件，不使用媒体处理器；不要据此假定支持相同的 Range 行为。缺失文件分支可能只渲染 `404.html` 而未设置 HTTP 404，因此应同时考虑状态与内容，不能将其当成具有统一错误契约的文件 API。

## 剪贴板提交

`POST /uptext` 接收 `application/x-www-form-urlencoded` 表单，字段为 `cont`。前端通过表单编码保留中文、换行及特殊字符。

该操作当前只写日志，不修改服务器剪贴板。`GET /c` 才会读取服务器剪贴板；图片接口依赖读取时生成的临时文件，刷新或多客户端访问不具备独立会话隔离。
